The inventory lists 47 screen numbers, of which SCR-13 and SCR-17 are removed (D-33) and not reused, so **45 screens are active: 22 pages (including the system page SCR-90) and 23 modals**. The mind map sync (D-88) added ten screens: four pages (SCR-22, SCR-24, SCR-55, SCR-62) and six modals (SCR-19, SCR-23, SCR-33, SCR-34, SCR-56, SCR-57); they are awaiting user review (D-102). Screen IDs are numbered by area (access 01 and 90, invoices 10s, recurring profiles and intake sources 20s, batch 30s, decisions 40, signing 50s, oversight 60s, entity administration 70 to 74, group administration 75 to 79, demo 80s). A new screen takes the next free number in its range (DF-38). "Opened from" says where a user gets in: `Navigation` means the sidebar or the login redirect, and `SCR-nn` means the parent page that has the button or link. A modal is always opened from a page, never from another modal. A removed screen keeps its row, reads "Removed (D-33)", and has no route, no card in the sitemap, no permission row, and no place in any flow.

## Reachability of Must stories

Every Must story is reachable through at least one screen that a Must story also uses, so cutting a Should story never leaves a Must story without a way in (lesson from Step 2). The checker walks the "Opened from" chain of the screens of each Must story and fails when a chain passes only through screens used by Should stories alone. The Group Overview (SCR-75) is built from US-06 and US-07, both Must, so the Group Admin home page survives when US-03 is cut. The Dashboard (SCR-60) is US-27, a Should, so no home page and no Must screen depends on it. One home page does depend on a Should story: the Requesting Department (D-90) has the acceptance queue (SCR-22, US-29) as its only page, so that role exists only while US-29 is in the MVP. No Must story depends on it.

The table lists the screens that disappear when one Should story is cut. US-11 and US-22 are no longer in it, because D-33 removed them from the MVP. US-29..US-32 were added to it by the mind map sync. A screen disappears only when no other story uses it.

| Story cut | Screens that disappear | Effect |
|---|---|---|
| US-03 | SCR-76, SCR-77 | The "Entities and limits" sidebar item goes. Entities, group limits, and the sector list come from the seed data (DF-13, DF-25). |
| US-09 | SCR-20, SCR-21 | The "Recurring profiles" sidebar item goes. Every recurring invoice becomes an exception. |
| US-19 | SCR-14 | The AP Accountant writes requests outside the system. The Reminder due filter on SCR-10 and the Request correction button on SCR-12 go too. |
| US-20 | None | The follow-up marker and history entries disappear from SCR-10 and SCR-12 only. |
| US-27 | SCR-60 | The "Dashboard" sidebar item goes for every role. |
| US-28 | SCR-61 | The "Audit log" sidebar item goes for all three roles that have it. |
| US-29 | SCR-22, SCR-23 | The acceptance queue goes, and with it the only page of the Requesting Department, so the role has no use. A service invoice with no ERP acceptance stays `Waiting for Goods` until the ERP records one (D-90). |
| US-30 | SCR-55, SCR-56 | The "Delegations" sidebar item goes for the Chief Accountant, the Payment Approver, and the Entity Admin, and so does the "On behalf of" marking. An absent signer is not replaced. |
| US-31 | SCR-24 | The "Mailbox" sidebar item goes. The AP Accountant uploads each file on SCR-10 (D-92). |
| US-32 | SCR-62 | The "Notifications" sidebar item and the unread count in the top bar go. New work shows by sidebar badges and list order only. |
